we-mpkg 2.4.10
=============

正式版。这一版只有一件事：安卓端的网络出口重新做，不再依赖固定代理端口。

## 问题
2.4.9 之前要在设置里手填 http://127.0.0.1:7890，等于把「本机 HTTP 代理 + 某个软件的默认端口」当成唯一解。
换代理软件、改端口、或者用纯 VPN（TUN）模式，填不对就搜不到创意工坊。

## 现在的做法：向系统要，不猜端口
- 启动时读系统当前网络：LinkProperties.getHttpProxy() 拿系统代理地址
  （代理软件「系统代理 / 允许局域网」、Wi-Fi 静态代理都会经这里下发），同时判断是否 VPN（TRANSPORT_VPN）。
- 结果写到 .cache/net.json，Node 每次请求按 mtime 读（2 秒节流）。
  切 VPN、开关系统代理、代理换端口都不用重启应用。
- 判断顺序：手动填的代理 > 系统 HTTP 代理 > 仅 VPN（直连，由系统路由进 VPN）> 直连。
- 安卓上显式代理连不通时会自动再退一次直连，避免旧代理失效后整个搜索瘫掉。
- 只认 http://：SOCKS 交给代理软件的 TUN / 系统代理接管，不在 Node 里模拟。

## 设置页
- 代理框默认「自动跟随系统」，7890 从占位符里去掉。
- 提示分四种：已保存手动代理 / 自动跟随系统（显示识别到的地址）/ 已检测到 VPN / 未检测到，当前直连。
- 「测试连通性」留空时测当前实际出口，不再报「代理为空」。

## 其他
compileSdk / targetSdk 维持 36。新增 4 组用例（net.json 解析只认 http、PAC 与空值退直连、
UI 与接口不再出现 7890 默认值、外壳字段完整性）。全量 125 通过 / 0 失败 / 1 跳过。
beta.1 真机验证通过后转正，功能与 beta.1 一致。
