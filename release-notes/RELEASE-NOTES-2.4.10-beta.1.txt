we-mpkg 2.4.10-beta.1
=====================

测试版，只发布安卓 APK。这次修安卓端的网络出口：不再依赖某个固定代理端口。

## 问题
之前要在设置里手填 http://127.0.0.1:7890，等于绑死「本机 HTTP 代理 + Clash 默认端口」这一种玩法。
换了代理软件、换了端口、或者用纯 VPN 模式（TUN），填不对就连不上创意工坊。

## 现在的做法：向系统要，不猜端口
- 安卓外壳启动时读系统当前网络：LinkProperties.getHttpProxy() 拿到系统代理地址
  （代理软件「系统代理 / 允许局域网」模式、Wi-Fi 静态代理都会经这里下发），
  同时判断当前网络是不是 VPN（TRANSPORT_VPN）。
- 结果写到 .cache/net.json，Node 每次请求按文件 mtime 读取，2 秒节流。
  所以切换 VPN、开关系统代理、代理软件换端口，都不用重启应用。
- 判断顺序：
  1) 手动填了代理 → 用手动（保留原有能力）
  2) 系统有 HTTP 代理 → 自动走它
  3) 只在 VPN（TUN）模式 → 直连，流量由系统路由进 VPN，不需要任何端口
  4) 都没有 → 直连
- 安卓上显式代理连不通时再自动退一次直连，避免被过期的旧代理卡死。
- 只认 http:// ：SOCKS 不在 Node 里做，交给代理软件的 TUN/系统代理接管。

## 设置页
- 代理输入框默认「自动跟随系统」，不再把 7890 当默认值；
  提示会区分：已保存手动代理 / 自动跟随系统（显示识别到的地址）/ 已检测到 VPN / 未检测到，当前直连。
- 「测试连通性」留空时会测当前生效的出口，而不是报「代理为空」。

## 其他
testSdk 无变化（compileSdk/targetSdk 36）。新增 4 组用例，全量 125 通过 / 0 失败 / 1 跳过。
