we-mpkg 3.0.0-beta.3

本版修复「双主题壁纸的第二套主题导入后永远调不出来」的老问题（与 Rust 无关）。

问题原因
旧逻辑在打包时把所有对象形式的 visible 一次性按 project.json 的默认属性值求值固化成布尔值
（日志里的「已固化 N 个图层可见性（其中隐藏 M 个）」）。这样确实能避免手机端把对象当 true
导致两套主题图层叠在一起，但代价是另一套主题被写死成 visible:false，导入后再也没有入口能打开它——
它的图层和纹理都还在包里，只是永远不显示。

新行为
由「用户属性」控制、且该属性确实写在 project.json 里的 visible 图层，打包时原样保留，交给壁纸引擎
运行时切换；其他求不出值的图层照旧固化。日志会分开统计：

  已固化 41 个图层可见性（其中隐藏 12 个）；保留 24 个属性控制的图层，交 WE 运行时切换

想恢复旧行为（全部固化）：设置环境变量 WEM_PRESERVE_VISIBLE=0。

注意
- 已经打包好的旧 mpkg 不会自动变好，需要重新打包一次。
- 桌面版壁纸引擎本来就支持属性切换，这版对它没有影响；移动端能否真的切出主题 2 取决于
  WE 手机端对 visible 对象的支持，如果两套主题叠在一起，把上面的环境变量设成 0 重打即可回退。
